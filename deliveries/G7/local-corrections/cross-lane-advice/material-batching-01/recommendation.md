## Minimum initial implementation boundary

1. Exact `THREE.Mesh` and exact `THREE.MeshStandardMaterial` constructors only. Preserve current skin/morph/instancing/custom hooks/custom depth-distance materials/geometry groups/draw-range/animation exclusions. No physical material, transmission, alpha map, alpha test/hash/coverage, transparency, wireframe, displacement, clipping planes, custom defines/extensions/shaders or existing geometry colors. Require all texture slots null initially, including envMap; scene environment remains native and shared. Reject any new unknown rendering property until reviewed. Source `vertexColors` must be false.
2. Require opaque defaults `opacity=1`, normal blending, `depthTest=true`, `depthWrite=true`, `colorWrite=true`, ordinary LessEqual depth, stencil disabled and polygon offset disabled. Merely matching unusual render states is insufficient: merging reorders primitives relative to other draws. Require source and ancestor render orders zero initially; otherwise keep native. Preserve side, shadowSide, toneMapped, fog, flatShading, dithering, precision, premultipliedAlpha, allowOverride and remaining rendering properties exactly. Custom scene override/render-sort/camera arrangements must trigger native fallback unless explicitly supported and tested.
3. Compare all rendering fields from pinned Material and MeshStandardMaterial, with only color RGB, roughness, metalness, emissive RGB and emissiveIntensity permitted to differ. Names, IDs and inert userData may differ. Do not use material.toJSON() colors as grouping/input precision: it serializes display-oriented colors and omits defaults. Read actual working-linear Color components. Finite values required; use float32 attributes, not bytes or an atlas. Group exact vertex layouts, castShadow, receiveShadow, frustumCulled, layer mask and supported order context. Preserve texcoords/attributes even if unused by this initial shader.
4. Preserve positive, nonsingular, orthogonal transforms for every source/ancestor and batch-relative transform; retain original positive-scale restrictions. Normals use inverse transpose, tangents direction transform with handedness retained. Native normal_vertex normalizes after transformation, so normalizing the copied normal earlier does not itself demand uniform scale. Still test nonuniform positive scale, parent transforms and tangent-bearing geometry. Reject shear/mirroring. CPU baking changes floating-point operation order and cannot promise bit-identical edge rasterization.
5. Opaque equal-depth/coplanar surfaces are order-dependent even with defaults. Three sorts opaque objects partly by material ID; one new material changes that ordering. Exclude known overlap/decal/order-sensitive sets, preserve original sorted primitive order within admitted batches where practical, and require paired pixels around contact/overlap edges against both batched and native neighboring objects. Internal ordering alone cannot preserve interleaving with outside objects. A discrepancy must narrow eligibility; it cannot be dismissed by enlarging the image threshold.

## Shader contract

- Each original vertex receives its material's float linear RGB color, float roughness/metalness pair and float RGB `(emissive * emissiveIntensity)`. Vertices from different original material domains must not be welded together. Every triangle has equal parameter values at all corners. Do not reconvert working-linear colors, clamp values, or multiply emissive intensity twice.
- Clone an eligible base material, set cloned diffuse to white and enable RGB vertex colors. Native color chunks then apply base color. Add uniquely named custom attributes/varyings for roughness/metalness and emission. Leave diffuse opacity opaque. Emissive initialization uses the encoded radiance; set neutral clone emissive/intensity consistently.
- Replace only initialization of totalEmissiveRadiance and the roughnessFactor/metalnessFactor initializers. The latter occur inside include chunks: replace the include with the pinned chunk text whose single initializer was changed, or use an equivalently bounded expansion. Blind replacement on the unexpanded physical shader will miss them. Preserve the rest of the chunks and all normal, BRDF, environment, shadow, fog, tone mapping and colorspace code.
- Require each insertion/replacement anchor exactly once; preflight against the installed pinned shader sources before suppressing any source. Use a stable versioned customProgramCacheKey encoding the shader revision, not material colors or an object UUID. Do not mutate global ShaderChunk/ShaderLib. Reject unsupported shader/Three versions and failed compilation back to visible native rendering; never leave white or missing geometry after an unsuccessful patch.
- Verify the clone's complete state after setup. Three r180 Material.copy does not copy allowOverride, and MeshStandardMaterial.copy recreates default defines. Therefore cloning alone is not a proof of preservation; initial scope should require default defines and explicitly preserve/validate allowOverride.

## Integration, mutations and ownership

Use a normal merged Mesh for these cross-material aggregates on both extension paths. Keep the existing same-material helper for remaining sources. Allocate sources once: cross-material batching must claim eligible originals before same-material batching, or integrate both into one orchestrator; never let two helpers suppress/restore the same source or batch each other's generated meshes. New helper ownership belongs to the runtime maker, not art/backend/release/auditor.

WorldRuntime currently updates batch copies after animation and before info.reset()/render; retain that ordering. Dispose/restore batches before tier material changes and reconstruct afterward. Keep info.autoReset=false and reset once before all renderer passes. No GLB edits are needed for this prototype.

Store source material identity plus an immutable deep snapshot of actual scalar/vector/color/Euler/define/hook values and material.version. Direct color.setRGB(), roughness assignment or emissiveIntensity changes do not reliably increment material.version. Recheck values before each render. Any changed rendering field, material identity, geometry/attribute/index identity/version/layout/draw-range, layer, hooks, parent or scene membership must remove that source's triangles and restore its current native rendering atomically in the same frame. A material-global change invalidates all referencing sources. Do not silently keep stale copied parameters. Invisible/hidden sources must leave the aggregate; when visible again, safely revalidate or remain native.

Retain existing attribute replacement/detach checks; also snapshot groups/draw-range/index array identity and bounding/culling inputs. Rebuilding working geometry after a rigid transform must not drop the newly added parameter attributes (the current original.working.copy(original.geometry) pattern would do so unless augmented). Copy current source buffers only; never write parameter attributes onto originals. Source material/geometry hierarchy and real mesh raycasts remain unchanged. Reserved rendering-layer suppression must preserve interaction layers, detect external layer edits, and never restore an old layer mask over a newer owner change.

For one active scene camera, main and transmission use the same view; retain per-source culling. Preserve off-camera shadow casters in merged geometry for shadow viewpoints. Include receiveShadow-only contributors if VSM is ever supported; current PCF/PCFSoft scope can reject other shadow modes. Additional cameras/ArrayCamera/shadow modes require per-pass correctness or native fallback, not reuse of a stale main-camera selection. Changing source frustumCulled must be detected; no enclosing-bounds shortcut may hide visible pieces.

Own only cloned aggregate materials/geometries and working copies. Dispose once, remove aggregates, restore source masks conditionally, and release owned copies before the session resource owner adopts the scene. Never dispose source materials/geometries or borrowed textures. Failure during construction must roll back all previous allocations/suppression.

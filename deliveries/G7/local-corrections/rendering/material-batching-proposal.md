# Proposed constant-parameter opaque material batch

This is a design input for separate architecture advice, not implementation or acceptance. Actual full-app native Chrome/NVIDIA diagnosis at source `d16e073` produced desktop 98/high,98/medium,51/low and portrait mobile 94/high,94/medium,48/low. All passes were counted. The fixed mobile bound is 80 for every active tier. Current ordinary rigid batching preserves PBR but leaves many different constant-material draws: actual reconstructed draw inventory contains 47 draws for transmission and 47 for main. Required content and selected quality must remain intact.

Three 0.180.0 local primary source read: `src/renderers/shaders/ShaderLib/meshphysical.glsl.js`, `ShaderChunk/color_vertex.glsl.js`, `color_pars_vertex.glsl.js`, `roughnessmap_fragment.glsl.js`, `metalnessmap_fragment.glsl.js`. The physical fragment creates `diffuseColor` from uniform `diffuse`, creates `totalEmissiveRadiance` from uniform `emissive`, and includes roughness/metalness chunks that initialize the respective factors from uniforms. All subsequent normal, lighting, BRDF, shadow, fog, tone mapping, color conversion and transmission-view processing remain Three's own.

Proposed narrow helper, subject to Parent allocation: copied opaque rigid geometry with per-vertex float linear RGB base color, float roughness/metalness pair and float linear RGB emissive already multiplied by emissive intensity. Each original triangle retains a constant value at every vertex, so interpolation reproduces the old uniform within normal float precision. Native vertex-color multiplication uses cloned white material (`vertexColors:true`). A stable custom-program key and shader substitutions replace only uniform roughness/metalness/emissive initialization with the corresponding varyings. No atlas, compressed color, altered roughness, shader approximation, added/removed effects or quality change.

Strict grouping: only eligible ordinary rigid `Mesh`, owned copied buffers, exact same constructor (`MeshStandardMaterial` initially), same material settings other than the four encoded constants and non-rendering IDs/names; same texture object bindings/matrices/color spaces, defines, shader extensions, side, blend/depth/stencil/polygon offset, fog, shadow flags, source render order/layers and compatible vertex layout. Prefer first scope with no texture bindings at all, no existing colors. Exclude physical, transmission, transparency, alpha masking/hash/coverage, custom hooks/programs, skins/morphs/instancing, object-space normal maps, clipping planes, vertex shader deformations and unsafe transforms. Differing texcoords cannot be silently dropped to group geometry; normals/tangents keep existing exact copy/transform semantics.

All original meshes/materials/hierarchy/pivots/buffers/raycasts remain unchanged and owned by the existing session. New helper owns only cloned aggregate material and geometry. Live transforms copy like existing portable merge; live source material identity or any material value/version, texture/program/layer/visibility/attribute/parent change removes that source from aggregate and restores native rendering. Original per-object frustum visibility is used; off-camera shadow casters remain for shadow viewpoints. Disposal restores layer masks and releases owned copies once; it never releases original borrowed textures/materials. Unsupported shaders/layouts remain native with honest counts. The aggregate is one normal `Mesh` draw regardless of `WEBGL_multi_draw`, so both enabled and suppressed-extension paths must be checked.

Required proof before admission: meaningful unit assertions for constant linear attributes, same-material render state, exclusions, live color/roughness/emissive mutation fallback, moving/hidden/detached sources, source raycast identity, original material unmodified, owned-only cleanup and quality rebuilding. Native Chrome rendered same-scene pixel comparisons with batching off/on under actual lighting, shadow and transmission; compare color/normal/roughness/emissive surfaces within small raster precision and require screenshots for independent view. Test actual GLBs on six viewports and high/medium/low with and without extension, all-inclusive counts and original actions; no assertion weakening. Rerun runtime recovery and paired animation tests. Draw profiles are still development diagnostics until frozen-source production evidence; leak absence and physical-device performance remain UNKNOWN/NOT RUN.

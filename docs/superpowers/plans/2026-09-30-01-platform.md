# YOR WORLD Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Delegated implementation is authorized. Follow [Delegation and work orders](../../planning/delegation-and-work-orders.md) for assignments and acceptance; this plan defines the platform task sequence and interfaces.

**Goal:** Deliver the complete semantic portfolio and durable owner-managed content/contact platform independently of the 3D world.

**Architecture:** One Next.js application with framework-independent server modules and shared schemas. Supabase supplies database, authentication, storage, and scheduling; providers sit behind narrow adapters.

**Tech Stack:** Next.js, TypeScript, React, Supabase, Zod, Vitest, Playwright, axe.

**Spec:** [Product design](../specs/2026-09-30-yor-world-design.md) and [Engineering and content](../../planning/engineering-and-content.md).

## Global Constraints

- C01–C15 in the product spec apply to every task.
- No invented biography, authorship, project metrics, deployment status, or asset rights.
- Public project, about, résumé, and contact information works without WebGL.
- Audio defaults off; explicit sound opt-in is required.
- Admin writes require verified identity, current owner authorization, and MFA.
- Only approved media and content revisions enter the public publication snapshot.
- Purchases, commissions, provider upgrades, and production-domain publication are separate owner decisions.
- Finished code changes are scoped, committed, and pushed; failures are reported immediately.
- Source assets and runtime assets are independently versioned; asset replacements cannot silently change an existing release.

## Review Focus

- Missing/unverified project data never produces fabricated public content — A1/A2.
- A revoked owner with a still-valid session cannot read private records or publish — A3.
- Concurrent edits or failed cache refresh do not corrupt the published revision — A4.
- Duplicate requests, quota races, and email failure preserve honest contact receipts — A5.
- Upstream API outages, arbitrary URLs, and secret-bearing errors cannot leak or block the portfolio — A6.

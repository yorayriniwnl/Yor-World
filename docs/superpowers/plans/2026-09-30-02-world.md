# YOR WORLD World Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Delegated implementation is authorized. Follow [Delegation and work orders](../../planning/delegation-and-work-orders.md) for assignments and acceptance; this plan defines the world task sequence and interfaces.

**Goal:** Produce a coherent room, exportable avatar, controlled entrance, and reliable render lifecycle before connecting the full interaction catalog.

**Architecture:** Blender sources produce versioned runtime groups and an asset manifest. One lazy client renderer consumes those groups; one camera director and one character director own motion.

**Tech Stack:** Blender 5.2.2 LTS, glTF tools, Three.js, React Three Fiber, GSAP, XState stable v5, TypeScript, Vitest, Playwright.

**Spec:** [Product design](../specs/2026-09-30-yor-world-design.md), [Art and experience](../../planning/art-and-experience.md), and [Validation and production](../../planning/validation-and-production.md).

**Visual baseline:** The latest workstation image, recorded in Art and experience, is the main reference: white furniture, a blue-and-white chair, purple/pink lighting with cyan fill, plants, gaming props, and a pegboard. Preserve that visible setup. Additional project props use secondary placements within the shared room geometry and anchors.

## Global Constraints

- All product constraints C01–C15 apply.
- No invented biography, authorship, project metrics, deployment status, or asset rights.
- Public project, about, résumé, and contact information works without WebGL.
- Audio defaults off; explicit sound opt-in is required.
- Reduced motion disables camera travel and pointer parallax.
- Entrance choreography is at most 8 seconds after required assets are ready.
- Exactly one camera controller and one full-body character action owner.
- Direct navigation, Skip, Escape, and failure handling cancel obsolete animation work.
- Frame-rate and loading numbers are targets until measured on the documented device/network protocol.
- Finished code changes are scoped, committed, and pushed; failures are reported immediately.
- Purchases, commissions, provider upgrades, and production-domain publication are separate owner decisions.

## Review Focus

- The entrance reveals real room geometry rather than a single attractive camera view — B1.
- Blender behavior/exported clips and materials differ in the browser — B2/B4.
- The seated turn clips through furniture or makes hands slide — B4.
- Skipping/failing/aborting loading leaves orphan resources or a stuck camera — B5.
- A good desktop render exceeds download, mobile, or sustained frame budgets — B2/B3/B5.

## Dependencies

Consume A1's shared schemas and application shell. B1's standalone source audit and Blender proof may proceed earlier under its work order; browser integration uses the shared contracts. Coordinator review checks each deliverable against the product, art, and engineering specifications without reopening blanket package approval. Unresolved external account targets, repository identity/visibility, and purchases affect only their dependent steps. The development harness is explicitly excluded from public production routes.

Art work has visual acceptance checks rather than artificial unit tests. Export/loader/state logic receives behavior tests. Source .blend files are versioned in the approved source storage; the Git repository tracks manifests, scripts, and appropriately sized runtime fixtures.

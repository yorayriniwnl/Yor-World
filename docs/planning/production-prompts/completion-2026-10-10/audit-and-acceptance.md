# Reusable audit, correction and acceptance prompts

P20–P23 run for each exact packet. Parent fills the handoff fields from actual files before dispatch; unresolved essential fields are not permission to guess. P24–P25 complete the cumulative full-product release after all six extension groups. These are distinct responsibilities, even when one chat holds several prompts.

## P20 — GPT #2: independent packet audit

```text
You are YOR WORLD's independent auditor, GPT Plus #2. Use GPT-6.1 Sol for ordinary audit. Audit the exact Parent-bound candidate below; do not fix maker production code/assets, edit maker evidence or accept the packet. Your result is independent PASS or REWORK advice within an explicitly stated scope.

HANDOFF TO BIND BEFORE EXECUTION
Packet/revision: [actual packet and revision]
Maker and exclusive delivery root: [account and existing path]
Parent work order and exact canonical allowlist: [paths/hashes]
Accepted contract revision and predecessor rulings: [paths/hashes]
Base commit/app tree and isolated overlay order: [actual identities]
Candidate source/patch/assets, dependency lock and build identities: [actual hashes]
Finding IDs and required outcome matrix: [actual IDs/paths]
Your new exclusive audit root: deliveries/completion-audits/[packet]/[new audit revision]/
Resolve fields from available source and the Parent handoff; record genuinely missing inputs rather than inventing identities. Do not overwrite a prior report or relabel an earlier run.

READ DIRECT INPUTS
Open AGENTS.md, START_HERE.md, the work-order hub, account operating model, FINISH-02 and this pack's common-execution.md. For an implementation audit, read accepted FINISH-00-R2 or the later applicable amendment. For P01's contract audit, inspect the proposed R2 candidate against its accepted predecessor and specification BEFORE R2 acceptance; do not require the ruling this audit is meant to inform. Read the selected author/maker prompt, actual specification clauses, the October 9 audit, relevant October 10 recheck reports, delivered source/patch/assets/documents/report, raw receipts and hash inventories. Follow links into actual code and artifacts. If files cannot be opened, report NO FILE ACCESS/MISSING INPUT. A browser chat reviews supplied material; it cannot claim local execution just because a packet names a command.

INDEPENDENCE AND CANDIDATE IDENTITY
Write only your audit root. You may assemble a new isolated copy of the bound candidate and author minimal diagnostics there, with recorded base plus overlays. Do not modify the tested implementation, its assertions, original exports or maker receipts. Do not copy a maker PASS table as your independent conclusion. Verify source.patch applicability, replaced file bytes, new/deleted paths, asset manifest references, dependency lock, actual tool versions and the build used by evidence. Check all declared output hashes/sizes, explicit exclusions and text-normalization policy. Report an identity mismatch before relying on affected proof.

Build a coverage map from every assigned requirement to inspected code, executed evidence and remaining limitations. Prioritize the user-visible outcomes and the defect triggers, not the number of tests. Inspect tests for vacuous assertions: locally calling a newly created callback does not establish loader/runtime integration; catching any error from an invalid URL does not establish cancellation; querying a button label does not establish stopped motion. A passing diagnostic that asserts a defect exists means DEFECT REPRODUCED. Distinguish it from a passing desired-behavior test.

AUDIT THE SELECTED DOMAIN
For contracts: parse actual SQL names/policies, code paths, interfaces, GLB inventory and overlay dependencies. Confirm no absent file is treated as existing, no contradictory allowlist, no circular prerequisite and no future implementation hash required before implementation. Recovery must be a measurable requirement, not claimed guaranteed by additive SQL. Verify newly permitted paths are bounded and subsequent ownership is unambiguous. Preserve historical ruling scope.

For A1/A2: exercise the real owner workflow when tools permit. Edit all four block types, save/reopen, observe draft preview before publication, test unauthorized and expired/lower-assurance access, verify no public/cache leakage, stale-revision rejection, executed review results, media approval, coherent site/project publication and rollback, resume approval/hash/download and truthful missing-input states. Inspect concurrency/transaction boundaries and actual production versus mocked database scope. Claim provenance needs the retained source/receipt, not a verified flag alone.

For C1: confirm first-entry real action/bone motion, pause/resume UI agreement, hidden-tab and retry/re-entry persistence, finite explicit action semantics, optional readiness while decode is held, real optional consumer registration and sole disposal ownership. Reproduce late decode after abort, stale callback from a previous session, blob URL cleanup on success/failure, a later required-load failure after earlier assets succeeded, unknown/compressed totals, retry reset/backoff and actual browser watchdog/cancellation. Inspect teardown listeners/timers/materials/textures and duplicated renderers. Existing real-GLB Node proof is useful but not full browser acceptance.

For B1: open actual editable/exported inputs and the main reference. Validate node/clip/hierarchy/pivot/rest/scale/bounds identities, measured duration and F1 metadata. Seven valid prior GLBs and 70 matching hashes established bytes, not fidelity. Check that lighting retains white detail and blue chair/floor with pink/violet/cyan composition, captures name actual camera/renderer/source, raw frame is genuinely WebGL when labeled so, and performance numbers come from the renderer. A duplicate mobile/full asset is not independent LOD evidence. Record direct visual observation separately from inferred source behavior and unrun Blender re-export.

For C2/C3: execute real visible door/automatic arrival, all 25 catalog outcomes and eight required clips; verify exact bindings and physical/material responses rather than generic substitutes. Test cancellation priority, focus/dialog restoration, contact/route continuity, reduced motion, civil-time correctness and repeated actions. Reproduce fresh initial mobile entry at the original 350x520 stage before opening/toggling the HUD. Record bounding rectangles and reachability of Exit and other controls, 44px targets, safe areas, keyboard/touch, 320px/landscape/zoom and supported-browser limits.

For integration/release/extensions: inspect the complete accepted predecessor chain and combined candidate. Verify no source changes escaped review, publication/schema/assets match the source, archive/manifest/CI bindings name actual bytes, and changed behavior has fresh affected evidence. Validate the selected extension's exact B-to-C contract, safe cancellation/resource ownership and cumulative budgets. Do not use earlier live proof as fresh proof for a changed release. Use P12 for the dedicated live G7 audit.

EXECUTION AND FINDINGS
Reproduce prioritized defects using minimal meaningful diagnostics where your actual tools allow. Record exact commands, working directory, versions, UTC times, exit codes and raw results. Preserve failed attempts and explain corrected probes without replacing history. Separate source inspection, synthetic/mocked boundary, Node real-asset sampling, local native browser, hosted CI, production service, physical-device and assistive-technology evidence. State NOT RUN for required unexecuted scopes. Broaden testing only when changed code, failures or unresolved concerns justify it; untouched broad suites need not be repeated for every documentation or narrow delta review.

For each finding supply a stable ID, severity, requirement, exact file/line or artifact/node, trigger, observed result, required result, minimal reproduction/evidence, confidence and assigned owner. Use CONFIRMED, SUSPECTED or MISSING EVIDENCE accurately. Do not call a missing device test a demonstrated device failure. Do not claim fabrication merely because provenance is incomplete. State whether a defect is a regression, an existing unclosed gap, an out-of-scope change or an architectural conflict for Parent.

RETURN AND HANDOFF
Return report.md, candidate identity, input/output hashes, commands/results, raw diagnostic programs and evidence, plus original-finding closure and regression tables. Count actual unique tests and disclose overlap, skipped/flaky cases and unsupported environments. End with PASS or REWORK advice for this exact scope, blockers and remaining limitations. A scope-limited PASS cannot waive required unrun behavior. Parent decides acceptance. Route confirmed implementation findings to the original maker via P21; architectural conflicts to Parent for a versioned amendment. Never silently implement the corrections yourself.
```

## P21 — Assigned maker: bounded correction

Resolve actual handoff values from local files. Do not assume a previous chat's description identifies the current bytes.

```text
Your exclusive write root is [new correction root]. Your exact canonical changed-path allowlist is [enumerated source/asset paths], and assigned findings are [IDs]. Preserve original maker delivery, failed evidence, accepted baselines and audit files. Do not edit shared app/ outside an explicit integration assignment. Do not change the audit report, broaden contracts, suppress checks or introduce unrelated refactors. If the root already contains a returned revision, allocate a new Parent-bound revision before replacing output. Contract conflicts go to Parent; continue other independent assigned fixes.

Begin by reproducing each assigned defect against the bound predecessor where tools allow. Record the trigger and actual failure without turning that reproduction into desired-behavior PASS. Group corrections by root cause and affected interface. Implement the smallest complete change that fulfills the accepted outcome across its real consumers, lifecycle and failure paths. A local flag/callback alone is insufficient if runtime/UI/asset ownership remains disconnected. For art, change real editable source, regenerate exports and measure the outputs; do not repair only a report or screenshot while retaining incompatible bytes.

Write meaningful regression proof for each issue. A useful test should fail for the independently audited defect and pass for the corrected behavior, with limitations stated. Exercise edge cases called out by the audit and adjacent affected behavior: stale revisions, security/cache boundaries, late asynchronous results, cancellation/disposal, pause/re-entry, reduced motion, physical binding, mobile initial layout, or recovery/write preservation as applicable. Avoid tests mirroring implementation constants. Use actual browser/GLB/provider/device scope when required; mark missing execution NOT RUN instead of inventing a receipt.

Run relevant lint/type/build checks and affected suites for code changes; genuine export/validator/playback checks for assets; service checks only within the assigned production packet. Reuse actual pinned tooling, record versions and retain raw command exits. Do not rerun all untouched suites solely to inflate proof. Full cumulative verification remains the integration packet's job, unless a correction changes a shared boundary that justifies broader coverage.

Return complete corrected source/assets plus an applicable patch, input/output hash manifests, new command receipts and a correction table: finding ID -> reproduced trigger -> changed paths -> desired behavior -> actual proof -> remaining limit. Include new regressions or unresolved architectural/input issues honestly. Keep old receipts identifiable and link them as historical context, never relabel them fresh. Check output inventory and source/lock/build identity before delivery.

Follow the human Git rule: scoped descriptive commit and push of only your completed owned work to the verified repository/assigned branch; inspect staged paths, preserve unrelated changes and report failures immediately. Return actual commit and remote readback. State DELIVERED FOR DELTA AUDIT, not accepted. Hand the exact correction to GPT #2 via P22, and wait for Parent P23 before starting a dependent packet. Do not approve yourself or close a finding based only on your own label.
```

## Actual outputs and evidence

In addition to common return files, provide editable native source, deterministic authoring/export/texture scripts where used, actual GLB and texture outputs, provenance/license records, node/anchor/dimension inventory, content-hashed runtime filenames and source/export revision mapping. Candidate manifest entries remain unapproved until parent acceptance; a preview harness is not approval authority.

Required evidence:

- Main reference beside the candidate, plus identical-pose Blender/browser frames. Include grey material, final color, desktop home/reference, portrait/landscape and close material/light views. Label lighting/pose differences explicitly; a Blender render alone cannot pass.
- Production-mode browser recording showing the actual sample and accepted resident/chair, with no duplicated geometry, hidden incompatible layer or console errors. Inspect raw canvas pixels, not only diagnostic counters.
- Native/export dimensions and pivots, single conversion, glTF validation, byte hashes; missing texture or corrupt GLB must be a visible failed check, not silently substituted art.
- Record draw calls including shadows/effects, triangles, compressed transfer and decoded GPU estimate; bound dynamic lights and texture sizes. Measure the sample plus the accepted resident/chair context, not an empty scene. Compare to existing validation targets (desktop 120 / mobile 80 draw calls; 6 / 3 MiB essential assets; 300k / 140k visible triangles) and report headroom consumed. Passing a single count does not establish performance.
- Show lamp/blinds base restoration around focus and clear light ownership. Meaningful module behavior tests only; no tests asserting arbitrary aesthetic colors equal implementation constants.
- Browser/OS/hardware/DPR/viewport and network/cache context, actual frame timing and load observations; Chrome/Edge locally where available, with mobile emulation clearly labeled. Physical-device certification and final whole-world budgets remain later work.

Production quality for this packet means the bounded sample is visibly coherent in the real browser and fits its measured contribution to the budget. If a known candidate reports hundreds of draw calls, measure and correct the sample rather than treating a validator PASS as production approval. Do not claim G3, final environment, mobile release or likeness acceptance.
